# ADR 0002：建立常驻制作人（兼策划）角色

- 状态：已接受
- 日期：2026-11-03
- 决策人：项目所有者
- 相关：[`docs/game-producer.md`](../game-producer.md)

## 背景

项目按任务卡逐张实现，每张卡有自己的验收，但没有一个角色对以下问题持续负责：

- 跨任务卡的设计一致性（数值、HUD、相机、工具行为、视听反馈）；
- 实现出来的效果是否真的是设计文档想要的那个；
- 验收是否有实际 build 的证据，而不是“代码写了、单测过了”；
- 哪些设计决定可以由执行者定，哪些必须回到项目所有者。

项目所有者明确要求：需要一个常驻的策划/制作人角色，设计细节与验收由它负责，关键决策随时上报。

## 决策

- 设立常驻“制作人（兼策划）”角色，由 superagent 在每张 ticket 中执行；里程碑由未参与实现的 worker 做独立验收。
- 制作人拥有已批准设计文档之内的细节决定权与验收判定权；方向、支柱、范围、预算/排期、美术风格、平台/技术栈、对外承诺、主观验收最终判定保留给项目所有者。
- 制作人必须用实际 build 的证据验收，区分“通过 / 有条件通过 / 待人工验收 / 不通过”；代码合并不等于验收通过。
- 关键决策按统一格式上报：要决定什么、背景、选项、建议、截止时间。
- 角色职责、检查清单、验收协议与节奏写入 [`docs/game-producer.md`](../game-producer.md)；所有 agent 通过根目录 `AGENTS.md` 被要求执行。

## 影响

- 每张 ticket/PR 增加制作人验收环节与验收对照表；交付从“代码完成”改为“有证据通过”。
- 每周五与每个里程碑必须留下验收记录；进度表 issue #36 只记状态与卡点。
- 设计文档之间的冲突有明确裁决顺序；改变已批准设计必须记 ADR。
- 项目所有者只处理保留事项，不再被日常细节打扰。

## 风险

- 制作人与实现者都是同一个 agent，独立性有限；用“里程碑由未参与实现的 worker 验收”降低自审偏差，主观项始终留给人。
- 制作人可能成为瓶颈；通过 §3.3“不要上报”的清单减少噪音，能由文档与证据决定的事直接决定。
- 角色依赖 agent 持续遵守 `AGENTS.md`；后续若更换执行系统，需要把该文件与 `docs/game-producer.md` 一起迁移。
