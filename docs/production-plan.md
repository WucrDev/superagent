# 从 0 到 Demo：实现路线（先做什么、什么时候画原画）

> 配套文档：`docs/over-the-hill-research.md`（调研 + 策划案）。本文只回答一个问题：**明天开始，按什么顺序做，才最不容易死。**

## 0. 一句话

**不要从原画开始。从“一辆车、一段烂路、一根绞盘”的灰盒原型开始。**
这个项目的生死线是“开车 + 被困 + 自救”的手感，不是画面；画面可以在灰盒里先定调，量产美术必须等垂直切片之后。

## 1. 为什么不是原画

| 常见误解 | 现实 |
|---|---|
| 先把美术画完再做 | 低多边形 + 氛围向项目里，概念图的边际价值低：最终画面是靠“引擎里的光照 + 调色 + 雾 + 镜头”调出来的，不是画出来的 |
| 先做大地图 | 地图是内容，内容是最后一个才该放大的东西；先把“一平方公里好玩”做出来 |
| 先做联机 | 联机是放大器：手感不对时，4 个人一起难受 |
| 先写完整策划案 | 策划案已经够了（见配套文档）；接下来要用可玩的东西证明它 |

原画的**正确用途**只有三个：
1. **目标图（target shot）**：3–5 张，回答“这游戏看起来是什么味道”；
2. **调色板与材质语言**：每生物群系一张色卡；
3. **UI 风格稿**：1–2 张，定 HUD 与地图的气质。
数量控制在 10 张以内，其余全部在引擎里迭代。

## 2. 五个阶段（每个阶段只证明一件事）

| 阶段 | 时长 | 要证明的事 | 若没证明 |
|---|---|---|---|
| P0 一页纸 | 1 周 | 团队对“体验目标”有同一句话 | 改到一致，别开工 |
| P1 灰盒原型 | 4–6 周 | 驾驶 + 脱困“有感觉” | 换方案，别加内容 |
| P2 垂直切片 | 8–12 周 | 30 分钟不出戏，且像一款商品 | 砍范围 |
| P3 内容生产 | 4–6 月 | 12 小时内容撑得住 | 缩地点数 |
| P4 联机与打磨 | 2–3 月 | 4 人稳定、可上架 | 延期或砍联机人数 |

## 3. P0：一页纸（第 1 周）

产出：
- 一段 120 字的体验描述（玩家会怎么向朋友描述这游戏）；
- 三条设计支柱（慢即是险 / 工具胜过马力 / 没有失败只有代价）；
- **一条 90 秒的“理想游玩片段”文字分镜**：从出发到陷车到自救到看见日落；
- 参考清单：3 款游戏 + 3 部电影/摄影集（做目标图时用）；
- 技术边界：平台、帧率、联机人数、内容量。

验收：团队 5 个人分别复述，说法一致。

## 4. P1：灰盒原型（第 2–7 周）—— 最重要的一段

### 目标
一段 **800 m × 800 m** 的测试场，一台车，四种地形，一根绞盘。**美术只允许用一个纯色材质 + 天空盒。**

### 具体任务（按周）

| 周 | 任务 | 验收 |
|---|---|---|
| W1 | 射线悬挂车辆（8 射线/轮），两档变速箱，油门/刹车/手刹，手柄支持 | 在平地上开 10 分钟不难受 |
| W2 | 四种路面（泥/岩/雪/深水）抓地曲线；坡度与断面地形 | 能明显感到“路不一样” |
| W3 | 绞盘：射线检测锚点、绳索约束、拉力曲线、自动/手动锚 | 一次成功拉出陷车会让人“松一口气” |
| W4 | 木板、千斤顶、维修包、车辆血量与损伤表现 | 四件工具各有独立使用场景 |
| W5 | 相机（第三人称 + 自由视角）、HUD 最小版、简单昼夜光照 | 能录出一段 60 秒“像那么回事”的片段 |
| W6 | 内部外测（10 人）+ 手感调参 | 8/10 说“愿意再开一趟” |

### 这一步唯一的 KPI
**“陷车 → 自救成功”这一刻的情绪强度。** 用问卷 + 录像回看判断：玩家是否在成功那一秒放松、是否主动再去找一个障碍。

## 5. P2：垂直切片（第 8–19 周）—— 美术在这里进场

### 顺序（不要颠倒）
1. **目标图 3–5 张**（1 周）：黄昏泥路、雪线远景、木屋内景、相机 UI 构图；
2. **一块 1 km² 的真实地点**（不是 4 km²）：一条主路 + 三个可选支线 + 一个木屋 + 一个观景点；
3. **低模资产管线跑通**：1 台车（600–1,500 面）+ 6 个环境件 + 1 套植被，全部进引擎；
4. **光照与调色**：一套后期（胶片颗粒、色偏、暗角），定死不准再改；
5. **音频**：引擎 5 层 + 环境 3 层 + 1 首主题曲；
6. **UI 与地图**：纸质地图、工具轮盘、相机模式；
7. **一条完整目标链**：观景点 → 救援 → 小径挑战 → 木屋改装，闭环。

### 验收（切片必须过）
- 30 分钟连续试玩不出戏（不许“先这样，以后修”）；
- 截图发给 5 个目标用户，4 个愿意加愿望单；
- 帧率达标（中端显卡 1080p ≥60）；
- 团队能据此估算“一个地点要几个人月”。

## 6. P3：内容生产（第 20–43 周）

只有切片验收后才放大，顺序：
1. 先做**工具**：地图摆点编辑器、目标配置表、地形笔刷预设、资产检查脚本（2–3 周，回报最高）；
2. 再做**第 2 个地点**（验证管线可复制），而不是急着做 4 个；
3. 车辆按类别补齐（每台 2–3 周，含手感调校）；
4. 目标从 12 个扩到 45 个，优先“不同类型”而非“更多同类型”；
5. 图鉴、磁带、明信片日记最后接（它们的成本低，但依赖地点与物种数据）。

## 7. P4：联机与打磨（第 44–56 周）

- 联机：主机权威 → 绳索确定性积分 → 车辙一次广播 → 中途加入/重连/主机迁移；
- 每两周一次 4 人外测；
- 平衡：只看“玩家是否愿意换车、是否愿意为长途带维修包”；
- 成就、云存档、本地化（17 语言，简中/繁中优先）、商店页素材（GIF 比截图更卖货）。

## 8. 各岗位第一周做什么

| 岗位 | 第一周 |
|---|---|
| 策划 | 写 120 字体验描述 + 90 秒分镜；列出 10 个“障碍类型” |
| 程序 | 搭项目骨架 + 射线悬挂最小可跑版本 |
| TA | 定低模规范（面数/贴图/顶点色），做 1 台车跑通引擎 |
| 美术 | 3 张目标图 + 4 张色卡（不做量产） |
| 音频 | 录 20 条引擎与轮胎样本，做 1 条 30 秒氛围 loop |
| 制作 | 排 W1–W6 任务与每周五的“可玩交付”节奏 |

## 9. 门禁与砍范围规则

- **P1 门禁**：外测 8/10 愿意再开 → 放行；否则调 2 周，仍不过就换驾驶方案（不是换美术）。
- **P2 门禁**：30 分钟不出戏 + 4/5 愿意加愿望单 → 放行；否则砍地点数与目标数。
- **P3 门禁**：第 2 个地点成本 ≤ 第 1 个的 60% → 管线可用；否则先修工具。
- 任何时候只能砍**内容数量**，不能砍**手感与画面调性**。

## 10. 六种死法（本类型特有）

1. 手感没调好就去做地图 —— 最常见，也最致命；
2. 用现成 WheelCollider 硬套，导致低速发飘、涉水穿模；
3. 把“无压力”理解成“没内容”；
4. 过早做 4 人联机，把物理推理重写三遍；
5. 让概念图定义视觉，结果引擎里做不出来，返工；
6. 单人做完 4 个地点才发现成本失控，没有 DLC 与 EA 的余地。

## 11. 工具链建议

- 引擎 Unity 6（URP）；版本锁定，禁止中途升级大版本；
- 建模 Blender（低模 + 顶点色），贴图 Substance/手绘图集；
- 地形 World Machine / Houdini 生成高度图，**手工摆点**做路线；
- 版本管理 Git LFS（美术资产走 LFS）+ 每次提交附一张截图；
- 每两周一个可玩 build 上传 Steam Playtest。

## 12. 一段示例冲刺（W3）

| 天 | 交付 |
|---|---|
| 一 | 绞盘锚点检测（树/石/车） |
| 二 | 绳索约束与拉力曲线 |
| 三 | 自动锚点 + 手动选择切换 |
| 四 | 音效与视觉反馈（绳绷紧、车身受力） |
| 五 | 两段测试地形 + 录像，团队打分 |

---

**结论**：先做灰盒，再做切片，最后才是量产原画；原画在 P0–P2 只负责“定调”，不负责“产出”。
